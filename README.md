시작 설정 화면 UI, 전투 HUD·카드명 라벨까지 포함합니다. 한글은 **나눔스퀘어 네오
Bold**로 렌더링합니다.

## ⚠️ 먼저 읽어주세요

- **게임 콘텐츠는 포함되어 있지 않습니다.** ROM, `CULDCEPT.DAT`, 실행 파일, 스토리
  대사, 카드 텍스트, 이미지·오디오 자산은 없습니다. 다만 UI를 제자리 교체하기 위한
  **검색 키**로, 짧은 기능성 UI/HUD/카드명 라벨(예: `ラウンド`, `手札`) 약 17개의 원문
  SJIS 문자열이 `opening_ko.py`에 들어 있습니다 — 스토리 텍스트가 아니라 위치를 찾기
  위한 라벨입니다. 게임을 정식으로 소유한 상태에서 **본인의 파일**로 사용하세요.
  한글 글리프는 시스템 폰트(맑은 고딕 등)에서 그려지고, 대사 원문은 전부 본인의
  `CULDCEPT.DAT`에서 읽어옵니다.
- **한국어 번역은 `dialogue_ko.json`(스토리 대사)·`cards_ko.json`(카드 텍스트)·
  `block_ko.json`(캐릭터 전투 대사)에 있습니다** — 한국어만 담기며, 일본어 원문은
  포함하지 않습니다(적용 시 본인 파일에서 읽음). 카드·대사는 위치(인덱스)로만
  매핑되고, 아이콘·제어코드·이름삽입 코드 등 원문 바이트는 적용 시 본인 파일에서
  다시 읽어 보존합니다. 완성형 2350자 폰트를 쓰므로 대부분의 한글이 표시됩니다.
- **아직 번역하지 않은 화면**(일부 텍스처 라벨·미크랙 나레이션 등)에서는, 한글 표시를
  위해 재활용한 한자 자리에 한글 글리프가 보일 수 있습니다(완성형 방식의 알려진 특성).
- **카드 449장은 전수 검증했습니다.** 카드명은 DLC나 별도 0x0d/0x8d 사본이 아니라
  본편 엔트리 1190의 한 레코드에 있습니다. 원본과 패치본을 카드별·필드별로 대조한 결과
  일본어가 있던 필드는 모두 변경됐고, 미번역 필드 0개·널 구분 오프셋 불일치 0개입니다.
  검수 방법과 스프레드시트 대조 결과는 [`docs/CARD_AUDIT.md`](docs/CARD_AUDIT.md)에
  기록했습니다.
- **길이 제약**으로 일부 대사·카드 텍스트는 원문 바이트 한도에 맞춰 간결하게 축약되어
  있습니다. 카드 능력 키워드 `巻物`(두루마리) 계열은 좁은 능력창에 맞추려고 압축형
  `권물`(卷物)로 통일했습니다.
- 연구·개인용. 게임의 저작권을 존중하세요.

## DLC 항목 이름을 번역하지 않는 이유 (검증 결과)

DLC 이름을 번역하면 게임에서 **DLC 가 통째로 사라집니다.** 에뮬레이터를 실제로 띄우고
"SD카드 확인" 단계까지 진행시킨 뒤, DLC 리소스가 메모리에 올라오는지로 다섯 조합을
비교했습니다.

| `load/mods/0004008c000f5700` 상태 | DLC 로드 |
| --- | --- |
| 폴더 없음 | 정상 |
| `romfs/` 카탈로그만 | 정상 — 단 Azahar 가 DLC 타이틀에는 romfs 교체를 적용하지 않아 **번역이 먹지도 않음** |
| `romfs_ext/` 빈 IPS 108개 | 정상 |
| `romfs_ext/` 한글 제목 IPS 108개 | **사라짐** |
| `romfs_ext/` **다른 일본어** 제목 IPS 108개 | **사라짐** |

마지막 줄이 결론을 정합니다. 멀쩡한 일본어로 바꿔도 사라지므로 글자·인코딩 문제가
아니라 **DLC 리소스 헤더를 수정하는 것 자체가 거부**됩니다. 리소스 파일은 앞 4바이트가
파일마다 다른 무결성 값이고(파일 크기는 0x04, 제목은 0x10, 페이로드 오프셋은 0x2B),
표준 체크섬(CRC32·Adler·FNV·djb2·sdbm·합·XOR, 여러 구간 조합)으로는 재현되지 않습니다.

그래서 v2.15 부터 DLC 오버레이를 **만들지 않고, 남아 있으면 지웁니다.** DLC 콘텐츠는
전부 정상 동작하며 게임 안 텍스트는 본편 한글패치가 적용됩니다. 목록의 **항목 이름만**
원문입니다. `apply_dlc_korean.py` 와 `dlc_ko.json` 은 무결성 값을 풀어낼 때를 위해
저장소에 남겨 둡니다.

## 게임 업데이트(ver 1.2)를 깔면 카드만 원문이던 이유

**`0004000E000F5700` 업데이트에는 RomFS 가 없고 `.code` 만 들어 있는데, 그 실행코드
안에 카드 이름·능력·설명이 통째로 들어 있습니다** — `CULDCEPT.DAT` 엔트리 1190 의
s0 섹션과 같은 내용이 오프셋 `0x308578`부터 153,786바이트로 박혀 있습니다.

업데이트를 깔면 게임은 카드 텍스트를 DAT 이 아니라 이 실행코드에서 읽습니다. 그래서
DAT 만 한글화하면 이렇게 갈립니다.

| 화면 | 읽는 곳 | 결과 |
| --- | --- | --- |
| 메뉴·퀘스트·규칙·북 정보 | `CULDCEPT.DAT` 1190 s2/s3 | 한글 |
| **카드 이름·능력·설명** | **업데이트 실행코드** | **원문** |

오랫동안 "카드만 일본어"였던 증상의 정체입니다. 업데이트를 깔지 않은 사람은 멀쩡하고
깐 사람만 카드가 원문으로 나왔기 때문에, 파일 검사로는 잡히지 않았습니다.

`apply_update_code.py` 가 이 실행코드를 한글화합니다.

```
python apply_update_code.py --dat 원본/CULDCEPT.DAT     --update "<가상SD>/title/0004000e/000f5700/content/00000001.app"     --out code.bin
```

- 업데이트 `.app`(평문 NCCH)에서 `.code` 를 꺼내 BLZ 해제합니다.
- 본인 DAT 에서 **원문 → 한글** 대응표를 만들어, 실행코드의 카드 문자열 1,943개 중
  1,927개(96.9%)를 그대로 재사용합니다. v1.2 에서 바뀐 몇 개는
  `update_extra_ko.json` 이 원문 SHA-1 을 키로 채웁니다.
- DAT 과 같은 규칙 — **제자리 교체, 원문 길이 이하, 남는 자리는 공백(0x20)**.
  카드 DB 구간 밖은 1바이트도 바뀌지 않고, 널 개수도 그대로입니다(4,101 → 4,101).

결과 파일은 `load/mods/00040000000F5700/exefs/code.bin` 에 둡니다. Azahar 로그에
`code.bin overriding built-in ExeFS file` 이 찍히면 적용된 것입니다. `설치.cmd` 는
설치된 업데이트를 찾아 이 과정을 자동으로 해 주고, 업데이트가 없으면 오버라이드를
두지 않습니다(실행 이미지가 어긋나므로).

## 설치했는데 게임 화면이 그대로일 때

파일 검사(`verify_install.cmd`)는 **디스크에 무엇이 있는지**만 봅니다. 설치는 멀쩡한데
화면에는 옛날 텍스트가 나오는 제보가 반복돼(이슈 #17), 남는 질문 하나를 직접 답하는
도구를 넣었습니다 — **게임이 지금 어느 `CULDCEPT.DAT` 을 읽고 있는가?**

```
python check_running_game.py        # 게임을 켜 둔 상태에서 (배포판은 게임검사.cmd)
```

실행 중인 에뮬레이터 프로세스의 메모리를 읽어, 로드된 카드 데이터베이스가 한글인지
원문인지 그 자리에서 판정합니다. 읽기 전용이며 윈도우 전용입니다.

| 결과 | 뜻 |
| --- | --- |
| 한글 카드 DB 를 읽고 있음 | 패치 정상. 화면도 한글이어야 합니다 |
| **원문** 카드 DB 를 읽고 있음 | 게임이 다른 파일을 읽고 있음 — 설치 폴더와 실행 폴더가 다르거나 게임 쪽 DAT 이 구버전 |
| 한글과 원문이 섞임 | 세이브 스테이트를 불러온 상태 |

`verify_install.py` 도 함께 강화했습니다.

- **카드 DB 번역 상태**: 엔트리 1190 의 네 섹션(카드 이름·능력 / 보조 / 규칙 / 메뉴)별
  번역률을 계산해, "UI 는 한글인데 카드만 원문" 같은 반쪽 상태를 잡아냅니다. 파일 크기와
  섹션 지문으로 어느 배포본인지도 판정합니다.
- **다른 에뮬레이터 폴더**: Citra/Lime3DS/포터블 `user` 폴더 중 로그가 더 최근인 곳이
  있으면 알려줍니다(설치한 폴더와 게임이 쓰는 폴더가 다른 경우).
- **세이브 스테이트**: 패치본보다 오래된 `.cst` 가 있으면 경고합니다. 스테이트에는 패치
  전 텍스트와 DLC 목록이 통째로 얼어붙어 있습니다.
- **DLC `.tmd`·티켓**: `.app` 만 복사해 넣으면 Azahar 가 DLC 를 인식하지 못합니다.
  게임 안에서 추가 콘텐츠가 통째로 사라진 것처럼 보이는 흔한 원인입니다.

## 적용 방법

두 가지 방법이 있습니다. 같은 한글 폰트를 쓰면 결과가 동일합니다 — xdelta 패치는
**나눔스퀘어 네오 Bold**로 만든 것이므로, 방법 A에서 그 폰트를 `fonts/`에 두거나
`--font`로 지정하면 릴리즈와 똑같이 나옵니다(다른 TTF면 글리프 모양만 달라짐).

### 가장 쉬운 적용 — v2.9 통합 릴리즈

일반 사용자는 **plaintext DLC 덤프나 파이썬을 준비할 필요가 없습니다.**
[최신 통합 패키지](https://github.com/snake75949494/culdcept-revolt-korean/releases/latest)에는
본편 xdelta와 DLC 카탈로그·수정 IPS 108개, 설치·카드 검증기가 함께 들어 있습니다.

1. ZIP을 새 폴더에 압축 해제합니다.
2. DeltaPatcher에서 본인이 추출한 일본판 Rev 2 `CULDCEPT.DAT`를 Original로,
   `culdcept-korean.xdelta`를 Patch로 골라 적용합니다.
3. 만들어진 패치본을 `CULDCEPT.DAT` 이름으로 아래 본편 경로에 둡니다.
4. ZIP의 `load` 폴더를 Azahar 사용자 폴더(보통
   `C:\Users\<윈도우 계정>\AppData\Roaming\Azahar\`)에 **폴더째 병합**합니다.
   v2.9에는 v2.8의 수정된 108개 IPS가 구형 패치와 같은 파일명으로 모두 들어 있어,
   기존 v2.4/v2.6 폴더에 병합해도 손상 패치를 빠짐없이 덮어씁니다.
5. 다음 세 경로가 각각 존재하는지 확인합니다.

   ```text
   Azahar\load\mods\00040000000F5700\romfs\CULDCEPT.DAT
   Azahar\load\mods\0004008c000f5700\romfs\ContentInfoArchive_JPN_ja.bin
   Azahar\load\mods\0004008c000f5700\romfs_ext\dice_simple_blue.dld.ips
   ```

   `CULDCEPT.DAT`는 본편 ID `00040000000F5700`에 두고, DLC 파일은 DLC ID
   `0004008c000f5700`에 둡니다. `ContentInfoArchive_JPN_ja.bin`을 본편 폴더에 넣으면
   적용되지 않습니다.
6. 게임과 에뮬레이터를 완전히 종료한 뒤 다시 실행합니다. 기존 세이브 상태를 바로
   재개하지 말고 게임을 새로 부팅하세요.

### 최신 이슈(#13) 해결 — v2.8

#13 로그의 첫 치명 오류는 `PC 0x00122204`에서 시작된 미매핑 메모리 읽기/쓰기
867,563건이었습니다. 게임 코드를 역어셈블한 결과, 직접 리소스 제목은 `0x10..0x2A`
27바이트인데 구형 생성기가 `0x10..0x2F` 32바이트를 덮어 쓰고 있었습니다. 그 때문에
`avatar_SORCERER.dla`의 페이로드 시작 오프셋 `0x2B=0x30`이 0으로 바뀌고, 게임이
대체 오프셋 `0x80`을 사용해 `0x34-0x80=0xFFFFFFB4` 바이트를 복호화하려다 프리징됐습니다.

v2.8은 제목 필드를 27바이트로 제한하고 `0x2B` 이후를 보존합니다. 원본 DLC 108개를
전수 검증한 결과 구형 v2.6은 97개 리소스의 보호 헤더를 바꾸고 34개 아바타에서 길이
언더플로가 발생했지만, v2.8은 두 수치가 모두 0입니다. 실제 게임의 복호화 함수를
`code.bin`에서 실행한 검증에서도 구형 패치는 미매핑 읽기로 중단되고 v2.8은 1회 처리 후
정상 반환했습니다.

v2.7 호환 ZIP은 `romfs_ext`를 포함하지 않아 **새 폴더에 설치할 때만** 안전했습니다.
기존 v2.6 폴더에 병합하면 구형 IPS가 남는 설계 결함이 있었고, #13에서 바로 그 상태가
확인됐습니다. v2.8 ZIP은 수정된 108개 파일을 전부 포함하므로 별도 삭제나 소거법 테스트
없이 그대로 병합하면 됩니다. `verify_install.cmd`는 구형 `0x2B` 손상 IPS와 #13의
`0x00122204` 로그 패턴을 직접 검출합니다.

### 방법 B — xdelta 패치 (빠름, 원본이 정확히 일치할 때)

## 무엇을 분석했나

- **`CULDCEPT.DAT` 컨테이너** — `(u32 오프셋, u32 크기)` 레코드 테이블 뒤에 엔트리
  데이터. 엔트리 개수 = `첫_오프셋 / 8`.
- **코덱** — `0x08`/`0x0c` = DEFLATE 계열 **canonical Huffman + LZ**(텍스트·폰트).
  이 타입은 디컴프레서·컴프레서 모두 순수 파이썬으로 구현(`culdcept/huffman.py`).
  `0x0d`/`0x8d` = 커스텀 **LZMA 레인지 코더**(572개). 비트 디코더는 표준 LZMA 와 같지만
  초기화·심볼 구조가 달라 표준 라이브러리로는 풀리지 않는다. `culdcept/lzma0d.py` 가 게임
  실행코드를 Unicorn 으로 에뮬레이션해 해제한다(본인 롬에서 `extract_code.py` 로 code.bin
  추출 필요).
- **비트맵 폰트** — CMAP(글리프 인덱스 → SJIS/ASCII 코드) + 여러 크기 섹션의 고정 셀
  **A4(4비트 알파)** 글리프. 위치 = `섹션 + 0xCE + 인덱스*bpg`.
- **시나리오 컨테이너** — 스토리 대사가 있는 곳. 코덱 엔트리가 아니라 자체
  `(섹션 오프셋, 크기)` 헤더로 시작하는 컨테이너이며, 각 섹션은 `0x08` 압축.
  대사 섹션은 `[스크립트][텍스트]` 구조, 텍스트는 null 종료 이벤트의 연속
  (`0x07`=페이지, `0x0a`=줄바꿈, `03 30 2f`=이름 삽입).
- **UI 버튼 아틀라스 (v1.8)** — 메뉴·필터·커맨드 버튼은 글자까지 통째로 그려진
  **ETC1/ETC1A4 텍스처**(엔트리 711·608·962). 3DS 는 ETC1 블록을 **u64 리틀엔디언**
  (=표준의 바이트 역순)으로 저장한다는 점을 규명해 디코더·인코더를 구현하고
  (`culdcept/etc1.py`), 원문을 지운 뒤 한글을 렌더해 **바뀐 블록만** 재인코딩한다.
  세 엔트리 모두 huffman 이라 `code.bin` 없이 완전 재현된다.
- **나레이션 텍스처 (v1.7)** — 양피지 가이드 나레이션은 시나리오 컨테이너 안에
  헤더 없이 저장된 **256×64/256×128 ETC1A4 텍스처**. 3DS 스위즐(8×8 타일 morton) +
  ETC1A4(알파 A4 + 색 ETC1) 구조를 규명해, 알파만 한글로 교체하고 색은 균일 진회색으로
  설정해 원본과 같은 스타일로 렌더한다. 겹쳐 저장된 다른 텍스처를 깨지 않도록 한글
  잉크가 있는 행까지만 덮고, 각 줄은 원본 잉크의 가로 중심에 맞춰 배치한다.

포맷 상세는 [`docs/FORMAT.md`](docs/FORMAT.md), 직접 빌드·번역 추가 방법은
[`docs/HOWTO.md`](docs/HOWTO.md) 참고.

## 폰트가 고정폭이라 생기는 일 (패딩 규칙)

이 게임의 비트맵 폰트는 글리프마다 폭이 없는 **고정폭**이다. 공백(0x20) 하나가
한글·한자와 똑같이 글자 한 칸을 차지한다. 번역문은 원문보다 짧을 때가 많고,
게임이 페이지·이벤트의 **바이트 위치**를 그대로 참조하므로 남는 자리는 반드시
채워야 하는데, 어디에 채우느냐로 화면이 달라진다.

- **대사 페이지** — 맨 뒤에 몰아 채우면 그 공백들이 마지막 줄을 넘겨 대화창
  밖으로 흘러 **아무 글자도 없는 빈 페이지가 한 장 더** 생긴다(이슈 #24
  "대사창 공백"). 그래서 `pad_page()` 가 **각 줄을 원본의 같은 줄 길이까지만**
  채운다. 한글(2바이트)은 원문 한자·가나(2바이트)와 폭이 같고 공백(1바이트)은
  그보다 좁으니, 이렇게 하면 어떤 줄도 원본보다 넓어질 수 없다.

- **UI 섹션(s3)의 짧은 라벨** — 이런 라벨은 다른 문장 안에 그대로 끼워 넣어진다
  ("맵이나 〈셉터〉 등"). 뒤에 붙은 공백이 그대로 보이므로 **널로 채운다**.
  s3 는 오프셋 참조라 널을 넣어도 뒤가 밀리지 않는다 — 같은 줄의 `マップ→맵`
  이 이미 널 패딩인데 벌어지지 않고 `セプター→셉터` 만 벌어진 것이 그 증거였다.

- **카드 DB(s0)·규칙(s2)** — 여기는 게임이 널로 구분된 필드를 **순서대로** 읽으므로
  널을 넣으면 빈 세그먼트가 생겨 뒤 필드가 전부 밀린다. 반드시 **공백**으로 채운다.

빌드는 예산을 넘겨 잘린 문자열을 전부 항목별로 보고한다. 잘림을 조용히 넘기면
화면에서 글자가 사라지는데(문장 끝의 물음표가 사라지던 이슈 #25) 무엇이 잘렸는지
알 수 없어 고칠 수가 없다.

## 번역 데이터

- `dialogue_ko.json` — **전체 스토리 대사**의 한국어(섹션·이벤트·페이지 인덱스 기준).
- `cards_ko.json` / `block_ko.json` / `missed_ko.json` — 카드 텍스트 / 캐릭터 전투 대사 /
  놓쳤던 중간 텍스트·한자 라벨의 한국어.
- `opening_ko.py` — 오프닝 대사(다듬은 버전) + UI/시작설정 라벨 한국어.
- `cards_extra_ko.json` — 카드 텍스트 열거 필터가 놓친 문자열의 한국어(오프셋 기준).
  선택창 '예' 등. 항목마다 원문 길이를 함께 적어 오프셋이 틀리면 건너뛴다.
- `ui_images_ko.json` — **UI 버튼 이미지**의 한국어 + 좌표(아틀라스별 엔트리·TS·크기,
  라벨별 지울 영역·그릴 위치·폰트 크기·색·지우기 방식). `apply_ui_images.py` 로 주입.
- `narration_ko.json` — **양피지 가이드 나레이션**의 한국어(엔트리·오프셋·크기별,
  256×64 35종 + 256×128 12종). `apply_narration.py`로 텍스처에 렌더·주입.
  (0x0d 엔트리 디코드에 게임 `code.bin`이 필요 — 저작권상 미배포, 각자 롬에서 추출.)
- `dlc_ko.json` — DLC 카탈로그 108개 고정 레코드의 한국어 제목·설명.
  `apply_dlc_korean.py`가 본인 DLC 덤프에서 원본을 읽고 카탈로그와 직접 리소스 제목을
  함께 교체합니다. `verify_dlc_patch.py`로 출력 IPS의 재현성을 검사할 수 있습니다.
- `update_ui_ko.json` — **게임 업데이트(v1.2) 실행코드**의 메뉴·통신 안내문 한국어.
  키는 원문 바이트의 SHA-1(원문은 담지 않는다). 카드 DB 영역만 훑던 `patch()` 로는
  닿지 않던 자리라 "로컬 통신을 사용해…" 안내문이 원문으로 남아 있었다(이슈 #24).
  `apply_update_code.py` 의 `patch_ui()` 가 널 패딩으로 제자리 교체한다.
- `verify_install.py` — Azahar의 본편/DLC 모드 경로, 실제 DLC 설치, 가상 SD 설정과
  LayeredFS 로그를 변경 없이 점검합니다(이슈 #10 진단용).
- `verify_cards.py` — 원본·패치본 카드 DB를 구조적으로 찾아 449장의 표시 이름·능력·
  플레이버·용어·전략과 널 구분 오프셋을 전수 대조합니다.

모두 한국어 번역만 담으며, 일본어 원문은 없습니다(적용 시 본인 파일에서 읽음).

> 참고: `apply_korean_font.py`(v0.1 발음 데모), `apply_korean_opening.py`(오프닝만),
> `apply_korean_full.py`(전체 대사). 최신 릴리즈는 전체 대사 패치입니다.
