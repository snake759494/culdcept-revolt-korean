# v2.8 — 이슈 #13 DLC 프리징 근본 수정

이 릴리즈는 `SD카드를 확인 중입니다...`에서 멈추던 이슈 #10/#12/#13의 직접 원인을
게임 코드까지 추적해 수정합니다. 카탈로그 전용 우회가 아니라 DLC 직접 제목 108개를
유지한 전체 패키지입니다.

## 원인

- DLC 직접 리소스의 제목 필드는 `0x10..0x2A` 27바이트입니다.
- 구형 v2.4/v2.6 생성기는 이를 32바이트로 보고 `0x2F`까지 널로 덮었습니다.
- `0x2B`는 제목이 아니라 암호화된 페이로드 시작 오프셋입니다.
- #13에서 마지막으로 적용된 `avatar_SORCERER.dla`는 `0x2B=0x30`이 0이 되어 게임이
  대체 오프셋 `0x80`을 사용했습니다.
- 리소스 크기 `0x34`에서 `0x80`을 빼면 `0xFFFFFFB4`로 언더플로되고, 게임의
  복호화 루프가 미매핑 메모리를 계속 읽고 썼습니다. #13 로그의 첫 치명 오류
  `PC 0x00122204`와 이후 867,563건의 오류가 이 흐름과 일치합니다.

v2.7 안전 ZIP에도 별도 문제가 있었습니다. ZIP 병합은 기존 파일을 삭제하지 못하므로,
`romfs_ext`가 없는 v2.7을 v2.6 폴더 위에 병합하면 손상 IPS 108개가 그대로 남았습니다.
#13 로그에서 v2.6 IPS가 계속 검색·적용된 것이 확인됐습니다.

## 수정

- 직접 제목 필드를 `0x1B`바이트로 제한합니다.
- 인코딩된 제목은 널 종료를 위해 최대 26바이트까지만 허용합니다.
- `0x2B` 이후 헤더와 페이로드를 바이트 단위로 보존합니다.
- v2.8 ZIP에 수정된 IPS 108개를 구형과 같은 파일명으로 모두 넣어, 기존 폴더에
  병합하기만 해도 손상 파일이 전부 덮어써지도록 했습니다.
- 설치 진단기는 구형 IPS의 `0x2B` 침범과 #13의 `PC 0x00122204` 메모리 루프를
  명시적으로 검출합니다.
- 설치되지 않은 DLC용 `original file for patch ... not found` 로그는 전체 패키지에서
  정상적으로 생길 수 있으므로 더 이상 패치 실패로 오판하지 않습니다.

## 검증

- 원본 plaintext DLC: 카탈로그 108개와 직접 IPS 108개 전수 재현 일치
- 구형 v2.6: 보호 헤더 변경 97개, 복호화 길이 언더플로 34개
- v2.8: 보호 헤더 변경 0개, 복호화 길이 언더플로 0개
- 실제 ROM `code.bin`의 복호화 함수 `0x001221D8` 실행:
  - 구형 `avatar_SORCERER.dla`: `offset=0x80`, `length=0xFFFFFFB4`, 미매핑 읽기로 중단
  - v2.8: `offset=0x30`, `length=4`, 정상 반환
- 자동 테스트 14개 및 Python 문법 검사 통과
- Azahar에서 게임을 새로 부팅해 수정 오버레이 구조와 실행 안정성 확인

## 적용

1. Azahar와 게임을 완전히 종료합니다.
2. `culdcept-dlc-korean-v2.8.zip`을 압축 해제합니다.
3. 안의 `load` 폴더를 Azahar 사용자 폴더에 병합하고 파일 덮어쓰기를 허용합니다.
4. 본편 패치가 아래 경로에 있는지 확인합니다.

   ```text
   load\mods\00040000000F5700\romfs\CULDCEPT.DAT
   ```

5. DLC 패치는 아래처럼 카탈로그 1개와 IPS 108개가 있어야 합니다.

   ```text
   load\mods\0004008c000f5700\romfs\ContentInfoArchive_JPN_ja.bin
   load\mods\0004008c000f5700\romfs_ext\*.ips
   ```

기존 v2.4/v2.6 폴더를 별도로 지울 필요는 없습니다. v2.8의 같은 이름 108개가 모두
덮어씁니다. v2.5/v2.7 카탈로그 전용 패키지로 다시 소거 테스트할 필요도 없습니다.

이 ZIP은 번역 카탈로그와 IPS 차이만 포함하며 원본 게임·DLC 콘텐츠를 포함하지 않습니다.
